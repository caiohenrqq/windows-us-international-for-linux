# Behavior and testing

## Input layers

XKB defines keys and their Shift, AltGr and Caps Lock levels. The file in `data/xkb/symbols` inherits `us(intl)` and overrides levels that differ from Microsoft's layout.

`data/xkb/types` adjusts Caps Lock behavior for `ß`, `µ` and `ç/Ç`. The user rules load these types only for `us_windows_intl`; the physical `us` and `br` maps remain unchanged.

The table in `data/compose` provides Windows combinations and literal fallback for unsupported accent combinations. It is generated by `tools/generate_compose.py` without reading the builder's personal configuration.

The addon keeps a separate composition state for each input context. It neither reuses nor resets Fcitx5's native state. The native engine still handles `Multi_key`. The addon sends no preedit text for the five accents it handles.

Compose files apply globally to the user. This project does not automatically detect the active layout. Other layouts may therefore behave differently from their native defaults.

## Automated tests

```sh
make check
```

The composition core can also be checked with AddressSanitizer, UndefinedBehaviorSanitizer and LeakSanitizer:

```sh
make check-sanitizers
```

LeakSanitizer needs access to inspect its own process. Running under `ptrace` or a restricted sandbox may prevent it from working; that is not the same as detecting a memory leak.

The suite covers:

- Accents, literal fallback, uppercase letters and characters outside the explicit table.
- Cancellation, Backspace and isolation between input contexts.
- Preservation of an ongoing native Compose sequence.
- Loading the real addon in an isolated Fcitx5 process without Wayland, X11 or D-Bus modules.
- Absence of preedit text, shortcut handling and focus changes in that isolated process.
- XKB maps, AltGr, Caps Lock, a single layout and the first four positions in a layout list.
- Unchanged physical US and ABNT2 maps.
- Installation and removal in temporary directories, including write failures, symbolic links, modified backups and later user edits.

The Fcitx5 test uses temporary XDG directories and does not replace the session's process. Tests install nothing into the real user's configuration.

The GitHub Actions workflow runs the same suite in an Arch Linux container as an unprivileged user. Check the repository's Actions tab for individual run results.

To regenerate the table:

```sh
python3 tools/generate_compose.py
make check
```

## Interactive test history

The implementation before the refactor was exercised using synthetic events through Wayland's virtual keyboard protocol with:

| Component | Version |
| --- | --- |
| Omarchy | 4.5.0-3 |
| Hyprland | 0.56.2-4 |
| Fcitx5 | 5.1.23-1 |
| Chromium | 155.0.8059.84-1, native Wayland |
| Foot | 1.28.0-2 |

Checks inspected Chromium field values and events, bytes received by the terminal and address-bar screenshots. Brazilian keyboard maps were also exercised using a complete virtual ABNT2 keyboard without changing the main layout.

This history does not establish graphical compatibility for every future build. The refactored code has automated Fcitx5 integration tests, but needs another graphical test pass before a stable release.

## Manual checks after installation

Test input fields, textareas, contenteditable elements, the address bar and the terminal:

| Sequence | Expected result |
| --- | --- |
| `'` then `a/e/c/m/s` | `á/é/ç/'m/'s` |
| `~` then `a/o` | `ã/õ` |
| `"` then `u` | `ü` |
| Backtick then `e` | `è` |
| `'` then Space | `'` |
| `"` then Space | `"` |
| Accent alone | No visible text or highlight |
| Accent then arrow key | No punctuation inserted; the first arrow key works |
| Omarchy Compose key, `m`, `s` | 😄 |

Check uppercase letters, AltGr, Caps Lock and application shortcuts. Repeat after logging out and back in. GTK, Qt, Electron, XWayland and applications that bypass Fcitx5 need separate tests; this suite does not certify them.
